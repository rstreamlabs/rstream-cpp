# Serve an application-owned TLS connection

Use [TLS passthrough](https://rstream.io/docs/tunnels/tunnel-protocols#tls)
when the C++ process should present the public certificate and own the TLS
handshake. The Engine carries the original TLS bytes to the rstream socket.
For edge termination, the Engine presents the public certificate. An
optional upstream TLS connection is then a separate handshake.

| TLS connection | Who configures trust |
| --- | --- |
| Agent to Engine | The C++ SDK verifies the Engine with its configured CA and server identity. |
| Public TLS passthrough | The caller verifies the application's certificate and forwarding hostname. |
| Public TLS terminated at the edge | The caller verifies the Engine's serving certificate. If upstream TLS is enabled, configure that handshake independently. |

See [SDK Engine trust](../002-configuration.md#trust-the-engine) for the
first connection. Edge TLS termination options and upstream TLS apply to a
terminated tunnel. With passthrough, configure those choices in the
application.

## Verify a passthrough service

Use a project or Engine that permits published TLS passthrough. Choose a
[stable](https://rstream.io/docs/tunnels/stable-domains) or
[registered custom](https://rstream.io/docs/tunnels/custom-domains) hostname
the project can request. Obtain a certificate covering that hostname before
starting the service. You can use a locally issued certificate for testing
with a caller that trusts its CA.

[Configure the checkout and the example path](../../example/io-rstrm/README.md#prepare-the-example-binaries).
Build the TLS example from the repository root.

```sh
cmake --build --preset conan-debug --target rstream-example-tls-http-server
```

Select the matching [context](../002-configuration.md). Replace the two
paths and hostname with the service's values.

```sh
rstream-example-tls-http-server /path/to/chain.pem /path/to/key.pem tls-demo.example.com
```

The program requests that forwarding hostname and prints the address assigned
by the Engine. Copy the host and port before the `(tls)` suffix into the
request. Use `curl.exe` on Windows.

```sh
curl -fsS --http1.1 --cacert /path/to/ca.pem 'https://tls-demo.example.com:443/'
```

Omit `--cacert` if the application certificate chains to a public CA trusted
by curl. Expect `Hello from rstream-cpp`. Stop the example with Ctrl+C.

The [TLS handler](../../example/io-rstrm/tls-http-server.cpp) wraps
the accepted socket in `asio::ssl::stream`, performs a server handshake
with a minimum of TLS 1.2, serves one Beast HTTP/1.1 request and shuts down
TLS. Configure client-certificate admission in the application when the
passthrough service requires it.
